# 开摊、交餐与订单状态衔接

## 本批范围

继续上一轮参考研究，围绕商家每天反复操作的开摊与交餐，以及学生操作后的状态反馈。参考项目 `yeshijingji` 的 `MMe.vue` 将营业状态与设置分组；烟火地图沿用自己的营业、位置有效期和接单规则。取餐面板延续已记录的 Square KDS 票据优先原则，不增加新的取餐、收款或订单接口。

| 查实的问题 | 本批处理 | 验证重点 |
| --- | --- | --- |
| 店铺营业首屏重复展示营业说明、备餐计数和经营设置 | 压缩重复说明；接单量、截止时间与支付配送按需展开；位置资料提前 | 默认收起、展开可操作、草稿及异步保存不因折叠丢失 |
| 接单台开摊／重新确认位置时看不到待确认地址 | 在对应按钮旁显示实际地址和更换位置入口；未确认位置先进入编辑 | 不自动定位、不将占位地址当作真实位置、恢复暂歇不刷新位置时间 |
| 直接打开位置链接时只展开编辑器，没有滚到对应区块 | 首次进入 `#location` 也定位到编辑器，并避开手机固定页头 | 无地图时仍可填写草稿；迁址继续审核，历史订单地址保持原值 |
| 商家取餐面板先展示核销按钮，金额、付款状态与餐点在后面 | 餐点、逐份要求、金额与付款状态集中在操作前；普通进度和联系资料按需展开 | 确认收款与核销仍分开，查码仅查单；资金、取消及迁址异常不能隐藏 |
| 学生取消／评价遇到未返回的自动刷新时，成功后的新状态可能漏刷新 | 采用已确认的操作响应，旧请求不能覆盖；需要补读时排队刷新 | 旧响应延迟、补读失败、支付与取消衔接、账号变化、评价重复入口 |

没有修改后端资金、库存、权限状态机，没有复制参考素材或引入虚构商户信息。服务器、真实支付和实体手机验收仍按原计划分别记录。
