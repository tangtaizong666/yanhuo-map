本轮落实单校园可控试点方案，保留现有技术栈、暖橙/奶油色视觉、自取与到摊付款、库存和价格复核、位置过期停单、模拟/真实隔离。开发端口仍为 5183/8087。同网络手机启动配置保持原样。

## 已落地的改进

| 问题 | 实施与约束 |
|---|---|
| 只读运营跨商家写入 | 统一 owner/具体 Django 权限判定；staff 标志不再是经营权限。商品、库存、订单、联系方式、报表、退款分别检查。 |
| 图片/请求体拒绝服务入口 | 锁定 DRF 3.17.2、Pillow 12.3.0；Image.open 先限制 JPEG/PNG/WebP；保留像素、重编码、EXIF 清理。JSON/Form 有界读取，超限 413；文件流超 5 MiB 中断，边缘与 Waitress 6 MiB 上限。 |
| 登录失败额度分散、代理地址混用 | API/admin 共用原子数据库账号/IP失败桶；统一可信 IP 解析，忽略未信任转发头；过期桶有界清理。 |
| 退款关闭仍可核销 | 服务端资金限制与 allowed_actions，未结案退款/异常付款期间禁止履约与核销、隐藏正常取餐凭证。 |
| 真实支付异常没有结案流程 | 受限运营表单；使用原商户配置重新查询并验签，核对编号/金额/币种，保存操作人、原因与脱敏依据。无法核实继续限制。 |
| 关闭退款不能补偿 | 保留多次尝试、显式幂等重试、每笔付款一个活动退款及成功累计限制；支持逐笔异常付款全额补偿、已验证外部全额退款导入。 |
| 商户间退款编号冲突、通知乱序 | 退款编号按原 mchid 联合唯一；成功退款先到/旧 CLOSED 后到也能保留旧状态并核验结案。 |
| 过期清理阻塞其他摊位 | GET 不清全站，下单仅清本摊位；worker 每条短事务、领取查询 skip_locked，资金限制记录不占满可清理批次。 |
| 身份与草稿串用 | API 头和正文处理均校验会话代次；旧成功/失败不覆盖新身份；餐袋按账号/访客隔离，明确确认后合并。 |
| 弱网重复创建与旧轮询覆盖 | 新商品持久化原键和原内容；服务端幂等；商家保存使旧读失效并排队补一次刷新。 |
| 存储失败与键盘操作 | 业务存储异常捕获并保留内存操作；取消订单使用原生模态对话框及焦点恢复；生产 bundle 可在存储 getter 完全拒绝访问时启动。 |
| 全量历史轮询和发现页查询增长 | 订单签名游标分页，默认30；活动/资金待处理分开轮询，个人计数服务端聚合。营业状态先筛选，交接点预取，评价全量聚合/20条预览。 |
| 缺少监测与恢复验证 | worker 心跳/累计异常/最老款项监测；健康探针不占游客限额；一键验证、旧库迁移回归、实际 pg_dump/pg_restore/媒体/加密虚拟配置恢复。 |

最终浏览器范围为41个fixture、1个生产存储场景和3个真实API集成，共45个通过。四种viewport检查包含在fixture中。Caddy验证使用官方Windows二进制及隔离上游，未运行完整Linux Compose；生产部署仍列为待验收。

此前全量PG发现核款命令在已有事务里调用 `close_old_connections()` 会关闭连接；现已保留调用者的事务连接，正常独立worker仍清理过期连接，上述354项为修复后完整复跑结果。新增当前请求用户的动作权限回归也已包含在最终计数内。

关键回归包括：权限矩阵、API/admin共享限流及实际 PostgreSQL 并发计数、伪造代理头、EPS插件不会被调用、超大JSON/表单、真实 HTTP 普通与分块上传拒绝、旧退款未结案不能核销、全额退款重试、原商户/金额/币种不匹配、外部退款、通知重放/乱序、多笔收款补偿、超时保持限制、双 worker 与跨摊位锁、历史数据迁移、账号切换旧响应、未知商品创建结果、历史分页和键盘焦点。

迁移回归使用实际旧版 schema 创建既有正式 CLOSED 与模拟 SUCCESS 记录，再升级。最初发现 PostgreSQL 延迟外键触发与索引 DDL 冲突，已将回填移至 DDL 后并在 PostgreSQL 立即校验约束；修复后的旧数据升级保留 UUID、交易号、退款号、金额、模式、原商户配置、库存及商家图片路径，历史 CLOSED 不被自动标为退款成功。

隔离恢复演练包含八个示例摊位以及额外的模拟付款、旧 CLOSED 退款、新成功退款、关联关系和资金证据。实际执行 pg_dump/pg_restore，并比较业务/账号/迁移表完整内容哈希；媒体比较原字节，加密支付配置只使用虚拟数据与临时密钥。
