# 日常经营与点餐指南

更新：2026-09-29。支付和配送继续使用原有模拟模式，不发生真实扣款，也不会安排真实配送人员。示例图片不是商家实拍。

## 商家每天从工作台开始

登录商家账号后进入 `/merchant`。最上面的“今天怎样营业”根据当前状态提供下一步：收摊时核对位置并开摊；暂歇时恢复营业；位置过期时主动确认位置；已经营业时优先处理待办。没有订单时不会再次要求开摊。

“暂停线上接单”只暂停新订单，学生仍能看到线下出摊。暂歇、收摊和暂停线上接单都不会刷新位置确认时间；已有订单需要继续处理。位置仍由商家主动确认，页面并不实时追踪摊位。

店铺资料可填写“通常出摊时段”，例如“工作日 17:00–21:00，雨天可能休息”。这只是计划，不会定时自动开摊，也不会代替当日位置确认。未填写时页面如实提示，不编造营业时间。

## 同一道菜，每一份都能说清楚

商家在商品编辑的可选信息中设置免费口味选项，例如“辣度：不辣、微辣、正常辣”。最多三组，每组最多八个选择；名称不可重复。保持名称清楚，付费加料或不同售价规格暂不放入这些选项。

学生在餐点详情、餐袋或结算页，可按“第 1 份、第 2 份”分别选择，并填写每份最多 100 字的备注。例如两份烤冷面，一份微辣不要葱，另一份不辣。整单备注仍用于整单要求。没有主动选择时，系统不会代填“默认口味”。

商家订单中逐份展示这些内容。商品后续改名或修改口味，不会改变已下订单。复购仍检查当前价格、库存和选项；旧选项已删除时应重新选择后再提交。自由备注是对商家的要求，不是平台对过敏原或制作条件的承诺；有特殊饮食需求时请先与商家确认。

## 告诉学生大概何时能做好

接单时默认使用店铺备餐时间，可按这笔订单调整为 1–180 分钟。制作中如有延迟，在订单内调整“还需要几分钟”并填写原因。学生会看到预计出餐时刻和商家说明，超过预计时间显示延迟提示，不会自动变成“已做好”。

出餐必须由商家确认。自取订单随后突出取餐地点、付款状态和取餐码；配送订单的出餐时间不等于送达时间。取消、退款、付款待核对等限制仍然生效。

弱网下，备餐调整若结果待确认，页面保留原请求供确认或重试。同一次重试不会把预计时间反复向后顺延。先处理待确认请求，再做新的调整；不要切换账号重新发起同一笔操作。

## 没有正在出摊的小摊，也能继续找

首页会区分：全部收摊、位置待确认、正在暂歇、当前区域尚未收录、筛选没有匹配、关注列表为空。可以清空筛选或切换区域；已有资料的摊位仍可查看和关注。

卡片上的通常时段明确标为“商家计划”，不能据此判断现在开门。加载失败时显示未确认，不把断网当作商家收摊。回到页面后会重新同步状态。

## 页面提醒与声音提醒

商家可主动开启并测试声音；页面显示同步、声音是否就绪。支持的浏览器中还可展开“系统提醒”，主动授权并发送一次试提醒。学生收到新的待取餐或到点状态、商家收到新的待处理订单后可触发本次会话提醒；进入页面时的历史记录不补发，切换账号或摊位重新建立基线。

这项功能依赖网页收到更新，**不是后台推送**。关闭网页、手机锁屏、切换后台后不保证继续送达。本轮没有开通短信、微信订阅消息或无人值守接单服务。当前局域网 HTTP 不满足系统提醒要求，会明确禁用；仍可浏览和使用页面提醒。浏览器通知需要用户授权和安全环境，移动浏览器的能力仍需真机检查。[浏览器通知说明](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API/Using_the_Notifications_API)

## 给账号保存一个恢复码

学生从“我的 → 设置 → 账号找回”，商家从店铺的更多设置进入账号安全，也可直接访问 `/account-security`。

1. 输入当前密码，生成恢复码。
2. 将恢复码保存在自己的密码管理器或安全离线位置，点击“我已安全保存”。明文只在这次生成后显示，不保存在网页本地存储，也不能再次向服务器查询。
3. 忘记密码时，从登录页进入“使用恢复码找回”，填写账号、恢复码和新密码。
4. 成功后重新登录。恢复码只能使用一次；需要时重新生成一个备用码。

重新生成、停用、修改密码或注销账号都会让旧码失效。找回会使旧登录失效；正常修改密码保留当前登录并使其他旧登录失效。并发请求仍以服务器锁定后的最新密码为准。[Django 密码与会话说明](https://docs.djangoproject.com/en/5.2/topics/auth/default/)

未事先保存恢复码且已忘记密码时，当前系统不能自动找回；仍需运营核验后处理，不使用订单、手机号或猜测身份绕过核验。恢复码等同于备用密码，不要发送给项目群或客服。部署人员更换 Django `SECRET_KEY` 会使现有恢复码失效，须安排重新生成；不在文档、日志或截图中保存真实码。

网络中断时，不凭页面失败判断修改未发生。重设密码结果未知，先用新密码尝试登录；生成恢复码结果未知，刷新状态后重新生成可见的新码，旧码随之失效。
