# 选餐、出餐台与线上份数操作指南

本轮围绕一人经营、自取为主的摊位。支付、配送仍为明确标识的模拟演练，不发生真实扣款或送货。

## 学生怎样选和取

1. 首页餐点区或搜索结果选择每份餐费：不限、10 元以内、15 元以内、20 元以内；可以按价格从低到高排列。预算包含边界价格，只筛餐点，不隐藏可线下到访的摊位，也不代表含配送费的订单总预算。返回页面、切换搜索类别会保留 URL 中的预算。
2. 卡片显示通常备餐分钟数，接单后看商家更新的预估。预估不代表保证时间；没有现场排队人数和虚构步行时间。
3. 结算先核对餐点、每份口味，再核对取餐位置、支付方式、联系方式与整单备注。餐点较多时可展开明细；手机底部保留合计与提交。
4. 自取订单出餐后，打开订单详情的取餐卡：认准摊位、8 位取餐码、付款状态、应付金额及下单时的地址。商家仍须确认收款，再核销。退款、付款待核或取消申请期间不显示正常取餐凭证。
5. 商家电话由本人订单接口直接提供，摊位暂不公开也能联系。没有电话时可以提交关联本单的反馈，等待运营人工处理；不是即时客服，不自动退款。

## 商家忙时怎样操作

订单页默认显示**出餐台**，仍可切换“全部订单”。待接单优先显示快超时的订单，制作中按预计出餐时间排列；未设置预估时按接单时间排列。餐点份数、逐份要求和整单备注直接显示。待付款预留、配送与异常订单保留处理入口。

同学到摊时，展开“查取餐码 · 搜索与筛选”，在“同学来取餐了”输入完整 8 位码。系统只查本摊待取的自取订单；重码时补完整订单号。先核对餐点、金额和付款状态，再确认收款、核销。查码本身不会收款或完成订单，错误码、重复核销和取消处理中仍受限制。

## 线上份数的三种操作

库存表示**留给线上销售、尚未被订单占用的份数**。现场卖了一份，不要求在系统逐笔记账；现场太忙或食材不足时，主动暂停供应或线上接单。

| 操作 | 什么时候用 | 结果 |
| --- | --- | --- |
| 给线上再加几份 | 新准备了一批可供线上点的食物 | 原子增加指定份数；不会解除暂停供应 |
| 暂停供应／恢复供应 | 缺料、临时做不了／确定可以继续做 | 只改变可售开关，库存数不变；取消返还不解除停售 |
| 更多：更正线上可卖份数 | 盘点发现线上余量填写有误 | 先核对最新余量和版本，再填写更正数量及原因；期间有下单、取消或补货则拒绝旧更正，要求重新盘点 |

编辑菜名、价格、照片等资料不再提交库存。新菜仍填写最初分配给线上的份数；零份只表示保存，补货后才可能可售。补货或更正结果未知时，用页面保留的原请求确认，不另建一笔。次日不自动恢复昨天库存或解除昨天停售。

## 接单量与本场截止时间

工作台直接显示待付款占位、待接单、制作中。在“接单量与本场截止时间”中可选：

- **限制同时备餐订单**：默认关闭；开启建议 5 单，可填 1–100 单。自取和配送共用容量，待付款也预留名额。出餐或终止后释放名额；降低上限不取消旧单，释放名额不覆盖手动暂停。
- **本场停止接新单时间**：开摊后填写，可留空，不能晚于预计收摊。到时仅停止新订单，下次重新开摊不继承旧截止。已预留订单不会因本项或满额失去原来的付款资格；真实收摊、资格和位置过期等仍按原规则处理。

这些限制只统计系统订单，不包含现场排队。需要时仍可手动暂停线上新单。

保存截止时间只修改本场截止，不会覆盖另一台设备刚设置的暂歇或恢复状态。若营业已结束或已经换到下一场，旧页面会要求刷新，重新核对后设置。

## 手机断网、锁屏时

商家页面在前台成功同步订单后，最多每 30 秒记录一次活动。任何一台设备正常同步都可更新；连续 90 秒未更新，学生会看到回复可能较慢的提醒。从未收到记录则显示暂无法确认。

活动记录不确认摊位位置、不标记收摊、不自动停单。锁屏后继续接收新订单，原有接单超时取消规则保持。网页通知受浏览器后台限制，不能代替可靠接单设备；公开运营前仍要完成真机和接单通知验证。
