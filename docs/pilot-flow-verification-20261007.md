本轮针对首次发布位置、地图迁址信息与仅找摊页面做浏览器核验。所有自动化使用合成资料或临时数据库；尚未开展真实商户现场试用，不能据此填写到访率、商户回访或操作耗时指标。

## 已复现的问题与修复

| 场景 | 修前实际结果 | 当前行为 |
| --- | --- | --- |
| 新批准商户保留预填地址，只补坐标后保存 | 请求只带坐标，后端要求的首次地址缺失，返回 `location_required` | 首次位置发送完整地址与经纬度；已有位置继续仅发送变更字段 |
| 顾客选中摊位，商家迁址后刷新地图 | 新地址与旧认摊说明、照片、电话和收摊时间混用 | 重新读取完整详情；更新中和失败时隐藏旧到摊指引，明确提供重试 |
| 详情请求未返回时关闭卡片或切换筛选 | 旧响应会重新打开已经清除的摊位卡片 | 清除选中时取消请求并使请求版本失效；账号变化同样处理 |
| 商户仅提供找摊信息，或曾保留交易餐袋 | 仍出现提前点单、付款和凭码取餐提示 | 隐藏该摊位交易侧栏与底部结算条，展示今天供应和到摊选购；餐袋内容继续保留 |

找摊商户的旧接单开关不会显示为“线上接单暂停”。有交易资格但暂时停单的商户仍保留餐袋与取餐说明。今天有、卖完和暂停供应的可见菜品均可打开详情。没有改动后端准入、库存、付款、旧订单或数据库迁移。
