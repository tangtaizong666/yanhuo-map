# 微信支付本轮交付与验证

日期：2026-09-26。没有商户凭据、正式域名或真实支付权限，**本轮未进行真实扣款、退款或生产部署**。当前示例环境不能发起微信扣款。

本文保留真实支付适配器接入阶段的验证。2026-09-27 后续加入的显式模拟体验不访问微信，其新增验证另见[模拟验证记录](simulation-verification.md)，操作见[模拟体验指南](simulation-guide.md)。历史测试项数不能作为新增模拟功能通过的证据。

## 已交付

- 订单出餐进入待取餐后，可在完成商户接入的环境选择 Native 扫码或手机外部浏览器 H5；未配置有明确提示，保留到摊付款。微信内 JSAPI 尚未实现。
- 后端金额与收款账号快照、RSA 请求签名与响应验签、通知验签解密、主动查询、关单、全额原路退款。
- 支付、退款号码先持久化再外调；未知结果保留占用，重复请求复用原号码。微信处理中禁止手工收款、取消与异常核销。
- 商家二次确认退款，学生查看进度。已制作食品不自动回补库存，付款与取餐分别记账。
- 收款按实际付款日期区分线上、线下；成功退款按实际退款日期统计，净收款可为负，不表示余额或利润。
- 独立后台查询任务、每商户配置、可选只读密钥挂载、运营文档与配送评估。

## 尚需正式环境验证

- 实际商户主体、经营准入、独立商户号及 AppID 产品权限、HTTPS 域名、可信客户端 IP、真实证书和公钥配置。
- 授权的小额 Native/H5 付款、关闭、原路退款、真实回调、账单核对和生产备份恢复。
- 当前机器没有 Docker/Caddy CLI，只完成配置语法和 Waitress 代理行为检查，未执行容器部署或 `caddy validate`。
- 过期且微信仍查无记录的未知支付保持占用；已关闭退款不自动换号重退；外部退款与冲突状态需要运营依据真实资金记录核对。自动任务只查询交易状态，尚未自动下载微信交易/资金账单。

接入步骤见 [微信支付说明](wechat-payments.md)，配送下一步见 [配送评估](delivery-assessment.md)。

## 支付入口可见性补充
