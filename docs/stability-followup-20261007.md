# WebKit 刷新回归与首次开摊修复 · 2026-10-07

本轮继续收尾已有版本：修正地图回归测试的滚动基线，并修复首次确认位置后开摊丢失预计收摊时间的问题。没有新增业务模式、素材、依赖或数据库迁移；没有执行部署或真人试用。

## 地图回归的原因与修正

提交 `6c117f8` 的[远端检查](https://github.com/tangtaizong666/yanhuo-map/actions/runs/37593825149)中，浏览器主回归 353 项通过、1 项失败。失败为 WebKit 地图后台刷新测试的滚动位置偏移 191 像素；其他检查任务、弱网重复与真实 API 流程通过。

本地原用例重复 5 次，3 次以 200 像素偏移失败。进一步保留相同的待处理选中请求与搜索框聚焦步骤，只取消后台刷新，仍捕获 `scrollY` 从 150 变到 350；期间卡片高度保持 888.4375 像素，详情读取次数保持 2。原因是 WebKit 的原生聚焦滚动可能在 `focus()` 返回后才完成，原测试过早记录了基线，误将聚焦产生的位移计入后台刷新。

修正仅限测试准备：先将控件滚到可见位置，再用 `focus({ preventScroll: true })` 聚焦，核对焦点和可见范围后记录滚动基线。三处滚动差值不超过 1 像素、详情更新、旧指引隐藏和焦点保留的断言继续保留；未修改地图生产逻辑、重试次数或断言容差。

三个相关场景在 Chromium 与 WebKit 各重复 5 次，共 30／30 通过。另临时在后台刷新完成处注入 `scrollBy(0, 80)`，修正后的原断言以实际偏移 80 像素失败，证明它仍能检测真正的后台滚动回归。临时注入已撤回。

## 首次开摊与收摊时间

原流程在商家尚未营业时保存位置和预计收摊时间，但之后点击开摊只提交营业状态与位置确认。后端创建新场次时不继承旧场次时间，导致刚保存的预计收摊时间消失。新增完整流程测试在修复前已复现失败。

现在仅商家接口提供 `opening_closes_at`：服务端确认当前为已收摊状态、且保存的预计时间仍在未来时才提供。工作台在开摊按钮旁明确显示「本次预计…收摊」，商家点击开摊时显式提交这一时间。公开接口不增加此字段，手机时间快慢不参与有效性判断。

后端创建新场次的默认规则不变：未显式提交的时间不继承，旧场次 `stop_orders_at` 不随开摊复制。若显示后时间已经过期，提交时仍拒绝，事务回滚，不误开摊。

异常路径检查包括：

- 尚无位置且未补齐有效坐标时只能保存地址草稿，不公开位置、不确认位置时间、不自动开摊；没有地图服务时，已有有效位置仍可明确确认。
- 空值、非数字和越界坐标不能提交位置确认；定位失败保留地址和坐标草稿。
- 首次位置确认尚未完成时，重复点击与回车不产生第二次提交。
- 首次确认已经保存但响应丢失时不显示成功；刷新工作台可以核对结果，不需再次写入。
- 首次保存位置和时间、刷新页面、开摊的完整链路保留预计收摊时间；手机时间偏移正负一天仍按服务端结果处理。
- 过期计划不随新场次提交；仅找摊商户仍不能线上接单。
