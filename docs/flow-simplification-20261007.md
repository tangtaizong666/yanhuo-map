# 页面与操作流程简化 · 2026-10-07

本轮围绕找摊、选餐、结算和首次填写商家位置做改进。没有增加业务模式，也没有更换图片、依赖或数据库结构。

## 用户现在怎样操作

- 学生打开小摊后，手机首屏能看到第一道餐点的价格和添加按钮。每道可见餐点仍能查看详情，包括暂停供应或售罄的餐点。
- 在餐点详情加入餐袋后，主按钮变为「去结算」，显示本摊实际份数和金额；可以继续选餐或明确开始再次加购。另一标签页移除这道餐点、清空餐袋或切换账号后，不保留过时的成功状态。
- 普通自取结算突出取餐地址、到摊付款和提交金额；不可用配送、未开通微信支付的原因按需展开。选填联系与整单备注默认收起，已有内容显示在摘要中，展开、收起和刷新均保留草稿。配送必填信息和模拟提示仍直接展示。
- 没有地图服务时，页面用简短提示和摊位列表找位置，隐藏无法使用的定位按钮。点击「查看位置与路线」会带到完整指引；关闭后键盘焦点回到原按钮。列表为空时可以直接查看全部摊位。
- 商家没有有效完整坐标时，主操作是「保存地址草稿」。这不会发布位置、续确认时间或自动开摊；已有位置或补齐有效坐标后，才提供明确的位置确认操作。资质资料单独收起，未保存输入继续保留。

## 设计依据与改动边界

遵循 [DESIGN.md](../DESIGN.md) 和既有[参考项目研究](reference-study-20261003.md)，重新对照本地参考项目的列表优先和状态分组方式。外部查看了 [Dribbble 餐饮应用作品页面](https://dribbble.com/shots/26528249-Food-Delivery-App-Design-UI) 与 [GSAP Showcase](https://gsap.com/showcase/)；本轮没有引入它们的图片、动效或代码。Recent 本次未能读取，不将其作为已完成的视觉对照。

| 当前问题 | 本项目采用的调整 | 核验方式 |
| --- | --- | --- |
| 手机摊位封面和不可用服务信息挤占菜单 | 保留真实出摊状态，缩短封面，详情页可查看完整服务说明 | 360／390 首道餐点添加按钮完整可见；768／1440 详情仍可用 |
| 加购成功后主按钮仍提示加购 | 成功阶段明确前往结算，并保留再次加购入口 | 逐份口味、十份上限、重复提交、跨标签删除和账号切换回归 |
| 自取结算并列展开不可用方式与所有选填字段 | 当前取餐方式优先，其他说明和选填字段渐进展开 | 草稿、配送能力变化、模拟模式、不确定提交恢复回归 |
| 无地图服务的大块占位挤走列表 | 简短提示、自然高度的完整位置指引、真实可用的按钮 | 四宽度截图、焦点与滚动、弱网详情更新回归 |
| 休息摊位卡片重复显示缺失时段文案 | 紧凑列表保留地址、真实状态和已填写的计划时段 | 四宽度候选列表可点击；不把过期位置当作营业确认 |
| 无地图时商家看见必失败的定位操作 | 先保存地址草稿，再明确完成位置确认 | 草稿请求只更新草稿字段；首次位置完整提交；回车和刷新保留输入 |

地图详情加载或失败时旧到摊指引仍隐藏，手动重试成功后才显示最新信息。组件保留挂载，使后台刷新不会销毁反馈草稿；只有原控件因隐藏失焦且用户未转向其他控件时恢复焦点。显式查看的意图可跨越后台重新请求，关闭或筛选仍取消该意图和迟到响应。同一账号更新资料不再误清除选中卡片；真正切换账号仍使原选择失效。

库存、价格、身份隔离、付款、位置过期停单与既有订单处理规则保持原有校验。截图使用已有示例配图和合成资料，不代表真实商户试用或实付验收。

## 验证记录

- 类型检查和生产构建通过；前端单元测试 15／15。
- 冻结源码后的完整 Chromium／WebKit 回归 354／354 通过（8.8 分钟），包含生产构建启动检查；没有增加重试或放宽业务保护断言。
- 独立临时数据库、媒体和回环服务上的真实 API 浏览器流程 15／15 通过（1.7 分钟），覆盖学生和商家自取、真实 Cookie 身份前置校验、模拟配送及退款恢复；测试结束后自有服务和临时资源已清理。
- 新增 18 个场景在两个浏览器中运行：选餐结算 8 个、地图发现 5 个、商家位置 5 个。既有测试按新页面真实展开选填区、再填写和读取草稿，继续保留价格、库存、身份、幂等和恢复断言。
- 360、390、768、1440 宽度检查无横向溢出；主要按钮触达区域、首道餐点入口、详情指引、选中和关闭焦点均有断言及截图。修前和修后截图已人工查看；未据此推断真实用户操作耗时。

首轮完整浏览器回归为 346 通过、2 失败：旧用例把指引卸载当作隐藏，等待期间暴露了同账号刷新误清除卡片的既存问题。修正真实接口 fixture 的 `user_id`、改为核验不可见状态，并补上账号值变化判定和身份刷新回归后，冻结版本独立全量复跑通过。首轮真实 API 脚本仍直接填写已收起的备注区，数项超时并达到 9 分钟运行上限；适配实际展开步骤后，使用全新临时库复跑通过。失败日志仍保留，没有把不完整运行记为成功。
