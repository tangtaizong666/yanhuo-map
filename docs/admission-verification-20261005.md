## 改动与边界

- `admission.py` 统一公开展示、新自取订单、线上支付及配送资格。资格到期、撤销、未授权或真实流动摊位只保留信息服务；营业、位置、接单开关及容量仍分别验证。商户开关、公开筛选、详情和实际请求使用同一规则。
- 既有订单仍可查看、取消、处理、查款、关闭支付和退款。资格失效时不再展示旧微信二维码／H5 入口，重复发起只核对原意图，网关创建前再次检查资格。模拟订单保持独立标识和网关隔离。
- `offline_payment_available` 明确授权现场付款入口。仅真实自取待取餐、未付款、无取消申请和资金冲突时可能显示；模拟、待接单、制作中、取消、退款、待核实和活跃线上支付均不返回真实码。
- 取消请求发出即收起付款和取餐凭证；结果未知与旧轮询不得恢复入口。按账号／订单保存待确认状态，提供确认取消结果及再次申请途径；资金查询和关闭仍可用。
- 商户首页按 `pickup_orders.eligible` 切换“今天出摊／接单台”。找摊模式保留地址、确认时间、开摊／暂歇／收摊、学生预览和已有订单，去掉无关接单准备与支付配送设置。
- 找摊菜品以 `display_availability` 保存“今天有／卖完了／暂时不卖”。新建无需填写库存；供应操作不改库存、版本或交易停售。恢复交易资格时按真实线上库存接单。旧菜品默认空值沿用已有状态。
- 迁址导致交易暂停时，核验结果贴近位置编辑操作，已有订单保留原地址并显示差异提醒。

数据库旧夹具补上已准入商户的可用支付配置，保留学生付款链接与商家脱敏断言；没有放宽生产门禁。压力测试保留 12 个并发工作线程和 1000 次唯一提交，改为每线程复用连接、最终关闭，减少每次请求都创建和释放连接的压力；新增校验 12 个独立数据库连接、1000 个序号无遗漏和只预留一单库存，不提高数据库连接上限。日志能够确认连接数耗尽，尚不能据此认定存在连接泄漏或确定操作系统回收时序。

PostgreSQL 首轮受旧脚本 180 秒总测试超时中断，不能算通过；完整套件现给 1200 秒上限，断言和数据库隔离保持不变。GitHub 工作流在构建成功后，即使普通浏览器回归失败，也继续运行弱网和真实 API 步骤并保留失败状态，避免再次无结果跳过。未触发远端 Actions，不把本地结果称作远端 CI 已通过。
