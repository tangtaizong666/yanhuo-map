# 可信找摊与商家开摊指南

本阶段继续使用明确标识的模拟支付与商家配送。申请入驻不会创建真实收款账户，补货、状态确认和订单处理仍保存到后端。

## 学生：先确认出摊，再出发

1. 首页默认看正在出摊的商家；“我的关注”可以看熟悉的小摊今天是否营业。“全部摊位”保留已收摊、暂歇或位置待确认的记录。
2. 有定位时参考距离，没有定位时查看最近确认信息。距离不代表路线步行时间；“商家确认”也不代表平台工作人员实时在场。
3. 进入摊位查看认摊说明和商家提供的现场照片。照片不是实时画面，位置过期时先联系商家。
4. 地图未配置或加载失败，仍可复制文字地址、查看地标、拨打已公开的电话。普通局域网 HTTP 不保证浏览器定位或剪贴板可用；复制失败会显示可选中的文字。
5. 没找到时直接点“没找到摊位”，游客也可提交。联系方式和补充说明选填，运营核实后处理；一次反馈不会自动下架摊位。
6. 关注后下次从首页返回；最近完成订单可“再来一单”，仍需核对当前价格、库存并分别结算。

“出摊中 · 暂停线上接单”表示商家线下营业但暂不接新网单，不等同于收摊。请勿将已经加入餐袋当作库存已预留；真正提交订单时仍由后端检查。

## 商家：自助申请或请团队协助

从页脚或“我的”进入“我是商家，申请入驻”，也可直接访问 `/merchant/apply`。没有账号先注册，已有普通账号可直接申请。

填写经营主体、摊位名称、联系号码、校园区域、品类、出摊地址说明。支持保存草稿；“提交入驻资料”确认信息并交给运营。进度包括草稿、待审核、需补充、已通过、未通过；需要补充时按页面意见修改后重新提交。

团队代录时，先由商家注册账号并将账号告知团队。运营在后台为该账号创建“团队协助”草稿，不能代替商家确认。商家登录后核对资料，再点“确认资料并提交”。运营无需知道商家的密码。

审核通过只建立商户与待准备的摊位，不自动公开、不自动获得交易资格，不开通支付与配送。商家进入工作台按清单补齐菜单与位置；运营在受限后台分别核验经营信息、公开展示和交易权限。经营证照不要通过公开商品图片上传入口传递。

## 每天开摊与补货

- 第一次添加餐点先填菜名、售价、现在可卖几份。照片等资料可以补充；零库存保存后仍不可购买，未上传实拍时不以示例照片假称现场。
- 位置优先在地图选点或定位后确认，普通操作不需要手填经纬度。地图不可用时保存地址草稿，请运营补齐；草稿不替代已经核实的取餐位置。
- 每天仍在原地时，核对地址后确认出摊。位置快到期时页面提醒，必须由本人确认，不能靠刷新页面或收摊自动续期。
- 忙不过来时点“暂停线上接单”；实际离开摊位使用暂歇，结束营业使用收摊。原订单仍需处理，收摊后查看未完成清单。
- “今天补货”填写本次新增份数，一次确认。下架商品补货不会自动上架。提交结果未知时保留原批次、重试确认，不能清浏览器数据后重加一遍。
- 开始营业时检查声音提醒并试音。现阶段提醒依赖网页在前台，不能依靠锁屏或关闭网页后自动响铃接单。

商家看到“找摊反馈”时，核对当时展示的地址与现在实际位置；原反馈仍交运营核实，商家确认位置不会自动将反馈标记为已解决。修改实际取餐位置继续触发原有交易资格复核。

## 运营后台

继续使用 `/admin/`，仅授权运营账号访问：

1. 查看商家入驻申请；代录用已有注册账号建立草稿，等待商家本人提交。
2. 退回或不通过时，先在申请详情填写并保存审核意见，再回列表选中申请，执行要求补充或不予通过；动作本身不弹出意见输入框。审核需有入驻申请的修改权限，仅查看权限不能审批。重复批准不会重复创建商户或摊位。
3. 完成经营信息、位置核验及菜单准备后，再分别设置对学生可见、经营核验和交易资格。不要为绕过地图或位置问题直接更改旧订单记录。
4. 按摊位与问题类型核查位置反馈，区分用户当时看到的信息与目前商家位置。自由说明和联系信息只供运营核实，不公开。
5. 经营数据中的回头客按完成订单与同一摊位的历史完成记录计算，真实与模拟分别查看；来源次数与实际到店人数不是同一指标。

## 分享与公开环境

商家和学生均可打开“分享小摊”，复制链接或保存二维码。扫码只打开公开摊位详情，不登录账号、不带取餐码，不触发付款。

部署人员配置 `PUBLIC_BASE_URL` 为公网根地址，例如 `https://campus.example.com`，不要填写用户凭据、路径、查询参数。生产环境必须使用 HTTPS。不配置时使用当前网页来源：`127.0.0.1` 链接仅当前电脑可用，局域网链接仅同网络且可互访时可用；换 Wi-Fi 后请重新生成体验二维码。

真实支付、正式地图与无人值守接单通知仍按各自接入方案完成准备，不能用模拟通过替代正式验收。
