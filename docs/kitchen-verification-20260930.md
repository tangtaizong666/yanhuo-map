## 重点结果

- 暂停供应后，取消归还、补货和盘点更正都不解除停售。商品资料编辑拒绝直接改库存，旧客户端得到明确升级提示；运营后台也使用同一更正服务。
- 库存版本随下单扣减、取消返还、增量补货和更正更新；先识别成功重试，再校验版本。提交期间有变化则整体拒绝，保留新订单扣减。
- 容量在摊位锁内统计，不反向锁定订单。待付款、自取、配送共用名额；降低上限不取消旧单。满额、商品停售和本场截止不阻断既有配送订单付款；实际收摊等原限制仍有效。
- 查码使用受权限和限流保护的 POST，只查所属摊位待取自取订单。重码须订单号，返回不泄露取餐码，审计不记录码值；查码不收款、不核销。真实联调完成了取消返还仍停售、CAS 重放、容量拒单，再在浏览器查码、确认收款及独立核销；重复核销被拒绝。
- 订单电话来自订单权限接口，隐藏摊位也可联系；取餐地址保留下单快照。付款待核、取消、退款等异常不展示正常凭证，反馈只关联本人订单并等待人工处理。
- 接单活动与位置、营业、接单开关独立。首次未知不称离线；多设备同步可更新同摊活动。页面使用服务端年龄与经过时间，不因手机时钟不准掩盖过期提醒。

## 发现并修正的问题

1. 搜索类别切换最初丢失预算／排序，已保留原 URL 查询参数并增加回归。
2. 取餐卡最初只有付款状态，已加入首屏应付金额。
3. 活动提示最初直接比较手机时间，已改用服务端活动年龄。重复相同响应不应重置前台已过时间，已增加时钟测试。
4. 库存更正成功或冲突后，折叠区最初自动关闭导致结果不可见，已独立保存展开状态。
5. 商家手机页原先提醒和多层筛选挤占首屏，出餐台改为紧凑提醒，查码与次级筛选集中展开；保留取消、售后和全部订单入口。
6. 另一设备暂歇后，旧页面保存截止可能回传旧营业状态。改为仅修改截止的请求并校验营业场次，既不恢复暂歇，也不把上一场草稿写入新场。

旧浏览器测试还适配了库存更正接口、新文案、逐份口味默认结构及重复标题的精确定位；评价回复测试改为自己创建独立模拟订单和评价，不再依赖其他测试先执行。
